# Security Policy

## Reporting a vulnerability

Email **info@northtek.io** with "OVERSTORY security" in the subject. Please do not open a
public issue for an unfixed vulnerability.

Include what you need to reproduce it: the command or request, the repo or input that
triggers it, and what you observed. A proof-of-concept repo is ideal for registry issues.

You can expect an acknowledgement within 3 business days and an assessment within 10. If a
fix ships, you will be credited in the changelog unless you ask otherwise.

## Scope

**In scope**

- The `@northtek/overstory` CLI, MCP server, and local `serve` app.
- The gate itself — in particular, any input that causes a claim to be reported `VERIFIED`
  when its cited text does not match the corpus. That is the core security property.
- The hosted registry (currently at `overstory-virid.vercel.app`): resource exhaustion,
  server-side request forgery, or any path that gets an unverified tree accepted as verified.

**Out of scope**

- Anything requiring a malicious local model or a compromised machine. If you point the tool
  at a hostile LLM endpoint, it can return hostile summaries — the gate limits the blast
  radius by refusing to mark unsupported claims verified, but it does not sandbox the model.
- Denial of service against your own machine via a deliberately enormous local repo.
- Reports generated by automated scanners without a working reproduction.

## Threat model, stated plainly

`overstory verify` proves **provenance and freshness**: the cited lines exist in the corpus
and their text is unchanged since the claim was written. It does not prove the claim is
*true*. Semantic support is a separate, build-time, model-generated tier that is labeled as
such. Treat a `VERIFIED` verdict as "this citation is real and current," not "this statement
is correct."

The `serve` app binds to `127.0.0.1` and is intended for local use. It has no authentication;
do not expose it to a network you do not control.

The hosted registry stores nothing. It fetches public repositories and published trees on
demand, verifies them, and caches the rendered result. It never accepts source code uploads,
and it cannot be used to publish claims that do not verify against the live repository.

## Known accepted risks

`@modelcontextprotocol/sdk` depends on a version of `@hono/node-server` with a moderate
path-traversal advisory. The patched line is 2.x-only and the SDK pins 1.x. OVERSTORY uses
the stdio transport exclusively and never serves static files through hono, so the vulnerable
code path is not reachable. This is re-checked on every dependency bump rather than
suppressed.
